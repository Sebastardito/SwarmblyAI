# SWIPs — Swarmbly Improvement Proposals

A SWIP is how a change to the wire protocol, the assembly algorithm, the
verification scheme or the governance rules gets argued before it gets built.
The process — when a SWIP is required, the review periods, and what a proposal
must contain — is in [`../CONTRIBUTING.md`](../CONTRIBUTING.md).

Files are named `SWIP-XXXX-short-title.md`, where `XXXX` is the zero-padded
number of the discussion issue that preceded the proposal. Open the issue first
(the [SWIP issue template](../.github/ISSUE_TEMPLATE/swip.md)); a proposal with
no prior discussion is usually a proposal for something already ruled out.

One SWIP per pull request, with no implementation in the same diff, so the
design can be argued without the code in the way.

---

*Una SWIP es la forma de discutir un cambio al protocolo, al algoritmo de
ensamblaje, al esquema de verificación o a las reglas de gobernanza antes de
construirlo. El proceso está en `../CONTRIBUTING.md`. Los archivos se nombran
`SWIP-XXXX-titulo-corto.md`, donde `XXXX` es el número del issue de discusión
previo, rellenado con ceros. Una SWIP por pull request, sin implementación en el
mismo diff.*
