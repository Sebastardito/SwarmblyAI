# T7.0 — `wasi-python` sandbox spike (macOS arm64, recipe 5 "data with code")

**Status: PASS — 10/10 checks. Recommendation: GO, conditional on a worker process + a
kernel-enforced disk cap (see §7).** The guest is a sealed CPython 3.15 with the scientific
stack; read-only data, a writable `/out`, no network, no processes, no host tools. The one
unbounded resource is disk, which the package does not cap and which a polling watchdog can
only bound softly (0.3–0.5 GiB overshoot measured).

Everything below was produced in this scratch folder; no repository was touched. The full
run log is `pytest.log` (`10 passed in 7.08s`).

## 4. What the guest sees (runner contract)

`runner.run(script, data_dir, out_dir, limits)`:

```
/data   read-only   grant of data_dir
/out    writable    grant of out_dir
(nothing else)      root=False: there is no "/" at all
```

API used (public names, with source in this venv):

* `wasi_python.run(...)` → `Completed`: `runner.py:134`; `Grant`: `_places.py:30`;
  `Grant(host, guest, *, writable=False)`; `Completed.stdout/.stderr/.trapped/.truncated/
  .exit_code/.fuel_used`: `_call.py:72`.
* `Session` / `Session.run` / `Session.checkpoint` / `run(..., snapshot=...)`:
  `runner.py:552`, `runner.py:942`, `runner.py:881`, and `runner.py:144` (snapshot argument).
* Limits are checked in `_limits.py:98`; stdout/stderr are capped per stream and named in
  `Completed.truncated` (`_call.py:72`, `_outputs.py`). With real host grants there is no
  `Completed.files` record (that exists only for `mounts=`; `_call.py:550`); `/out` files are
  read directly from the host directory by `runner.collect()`.

Verified inside the guest: `os.listdir("/")`, `/tmp`, `/etc`, `/home` → `ENOENT`; no `$HOME`
directory (`HOME=/nonexistent-home`); no host path is resolvable. `os.getcwd()` prints `/`
but relative `open()` fails `ENOENT`, so model code must use absolute `/data/...` and
`/out/...` (or call `os.chdir("/out")` itself). Every call is a new wasmtime instance, a
new private HOME, new descriptor table; nothing survives between calls. `out_dir` must be
empty at entry (the runner refuses a reused directory).

`runner.py` adds host-side guards the package lacks:

* `_Watchdog` polls `out_dir` every 10 ms; above `max_out_bytes` or `max_out_files` it sets
  wasi-python's `cancel` event (`runner.py` docstring at `wasi_python/runner.py:216`:
  stops within 5 ticks of 10 ms). If it trips, the over-budget regular files are deleted
  (`_discard_over_budget`) and the result is marked failed.
* `hard_grace_s=5` wall backstop around the package deadline.
* `collect()` walks `/out` with `follow_symlinks=False`; regular files are opened with
  `O_NOFOLLOW`, symlinks are recorded as `{"type":"symlink","target":...,"followed":false}`.
* `data_dir`/`out_dir` nesting and cache-dir nesting are refused; the cache is `0700` and
  never granted; `TMPDIR` is pinned to `./.tmp` so wasi-python's private copies stay here.

The only host processes in this folder are the pytest process and two short-lived children it
spawns: the cold-latency process (check 10) and `hard_cap_worker.py` (check 8).

## 5. Security model, read from the source

**Grants are real wasmtime preopens, and read-only is enforced by wasmtime, not Python.**
`_call.py:505` calls `wasi.preopen_dir(p.walked.path, p.guest, p.writable)`; wasmtime-py's
signature is `preopen_dir(path, guest_path, fs_mutable=True)`, so `writable=False` becomes
`fs_mutable=False` in wasmtime's WASI/cap-std layer. That is why writes to `/data` return
`PermissionError` (EPERM), not an application-level check. **Mounts are different**: a
`Mount(FileProvider, ...)` is served by the package's Python filesystem code, where
read-only is checked in Python (`_fs_paths.py:140`, `_fs_descriptors.py:211`). This spike
uses no mounts, so none of that Python path is on the attack surface.

**Host-path setup is hardened.** `_places.py:47-52`: every host path, `root` included, is
walked one component at a time from `/`, judging each link, and every rule compares
identities (device + inode), never spellings. Wasmtime then opens each preopen itself, and
before the guest runs a check module reads back each preopen's identity and compares it with
the walk (`_call.py:674` → `_places._check_preopens`, `_places.py:438`).

**Imports.** `_linker` (`_call.py:988`) defines WASI snapshot-preview1, shadows
`poll_oneoff`, and defines exactly one custom import: `host::call` (`_call.py:1007`), bound
to `NO_HOST` when no `host=`/`tools=` is given. With no mounts, a second linker shadows only
`path_open`, `fd_close`, `fd_renumber` to count open files (`_call.py:1032`), forwarding all
other calls to wasmtime. WASI p1 has no sockets, processes or dynamic loading, so the
absence of `getaddrinfo`, `_ssl`, `fork` and `ctypes.CDLL` is structural, not a Python
denylist.

**Host doors that exist in the package and are NOT used here:** the `host=` byte callback
(arbitrary request/response between guest and host code), `tools=`/`gate=` (host functions
with budgets), `mounts=` (Python-served files), `root=True` (a writable `/`), `import_path`,
`stdin`, a caller-supplied `artifacts=`, `env=` (arbitrary guest variables; only the
`_PYTHON_*` prefix is refused), and `cache_dir=` (host-side `.cwasm` writes). Any of these
changes the trust model; `host=` is the largest door and must stay `None` for this recipe.

**Private host-side directories.** wasi-python writes per-process `0700` folders under
`tempfile.gettempdir()`: a ~70 MB copy of the stdlib zip, matplotlib's extracted data, an
empty guest HOME, and stdin. These are host directories outside the wasm sandbox, with their
own lock/sweep protocol (`_private_dirs.py`). The runner pins `TMPDIR` to `./.tmp` so they do
not escape this folder. A second subtlety: the first copy records a stamp whose `ctime` is
still settling, so the **second call in a process silently re-copies ~70 MB** before the
stamp stabilises (observed: run 1 0.200 s, run 2 0.040 s, run 3 0.008 s). Harmless normally;
it matters for `RLIMIT_FSIZE` (§6).

**In-process TCB.** The guest runs inside the host process via wasmtime. There is no OS
process boundary: a wasmtime or CPython-wasm memory-safety bug would be a host compromise.
Within the scope of this spike (API-level escapes) the boundary held, but production should
still put the whole thing in a disposable worker process with rlimits — which also solves
the disk problem.

**`chmod` is not a control.** The guest's `os.chmod` returns success and changes nothing;
guest-reported metadata success must not be trusted.

## 6. Disk: the one finding that needs a guard

The package's limits are `fuel`, `deadline_s`, `memory_bytes`, `output_bytes`, `file_calls`
and `open_files` (`runner.py:68`, `_limits.py:98`). **There is no bytes-on-disk or inode
cap.** In ~1.0 s the guest wrote **8.2–11.7 GB** (logical and allocated) to `/out` before the
deadline — 7.7–11.0 GiB/s apparent on this M-series/APFS machine (page-cache speed; not
durable throughput, but a small volume fills just as fast). A 2 GiB file is ~0.2 s of work.

A polling guard is **soft**: trigger at 128 MiB produced peaks of **576–592 MiB**
(448–486 MiB overshoot) because the guest keeps writing during the ~50 ms cancellation window. It bounds
*persistent* usage (the runner deletes the over-budget file) but not peak. A **hard** cap is
available with `RLIMIT_FSIZE` in a dedicated worker: after warming (two calls) and setting
`sigaction(SIGXFSZ, SIG_IGN)`, the kernel stopped the write at exactly **64 MiB** with
`OSError: File too large`. `hard_cap_worker.py` demonstrates this; `RLIMIT_FSIZE` must exceed
the ~70 MB stdlib copy (or be applied after two warm calls), and applies to the whole process,
so it belongs in a short-lived worker, never in the API server.

Recommended layered guard: soft watchdog at 256 MiB + `RLIMIT_FSIZE` hard backstop at
~320–384 MiB + file-count cap + discard over-budget output. For a 64 MiB hard cap, pre-stage
the stdlib copy or use a quota'd volume.

## 7. Go / no-go and conditions

**GO** for adopting `wasi-python==0.1.5` as the recipe-5 sandbox, under these conditions:

1. **Pin exactly** `wasi-python==0.1.5` and `wasmtime==50.0.1`, lock with the wheel SHA-256
   above (`pip --require-hashes`), vendor the wheel. Treat upgrades as a new spike: the
   package's `__init__` marks the modules `runner`, `mounts` and `cli` (and everything not
   re-exported) as internal, so only the named public API is promised across releases.
2. **Run each call in a disposable worker process**, not in the API process. Pre-warm two
   plain calls per worker (the stdlib zip copy and its stable stamp), plus one metered call
   only if `fuel` is used; keep a small pool (2–4) and bound concurrency. This gives kill-on-timeout, rlimits, and isolation from wasmtime bugs.
3. **Hard-cap disk:** `RLIMIT_FSIZE` (≈320–384 MiB, or 64 MiB after pre-staging) **plus**
   the 256 MiB soft watchdog; cap file count; discard over-budget output; alert when the
   guard trips. Do not point `/out` at a directory containing anything else.
4. **Limits defaults:** `deadline_s=10` (15 for xlsx), `memory_bytes=256 MiB` (128 MiB
   works for pandas import; 512 MiB for large workbooks), `output_bytes=1–4 MiB`,
   `fuel=None` (metered compilation costs 5.3 s / ~4 GiB cold; the deadline is enough),
   `max_out_bytes=256 MiB`, `max_out_files=10_000`, `max_open_files=1024`.
5. **Grant exactly** `/data` read-only and `/out` writable; `root=False`; no `host=`, no
   `tools=`, no `mounts=`, no `import_path`, no `stdin`; minimal env; cache dir `0700`
   outside every grant; `TMPDIR` pinned.
6. **Collect `/out` without following symlinks** (`O_NOFOLLOW`, `follow_symlinks=False`) and
   reject paths that resolve outside; relative symlinks pointing outside *can* be created
   even though wasmtime refuses to follow them.
7. **Tell the model the contract:** absolute `/data/...` and `/out/...`; the guest cwd is not
   a usable directory. If relative paths are desired, prepend `os.chdir("/out")` in the
   runner (not done here, to keep the script verbatim).
8. **Belt and braces:** run the worker as an unprivileged user with an outbound firewall /
   network namespace, even though the guest has no socket API. Keep the artifact cache and
   `.tmp` monitored and cleaned.

If the architecture insists on in-process execution, this spike is **NO-GO on disk alone**:
the package cannot bound bytes written, and the soft guard overshoots by hundreds of MiB per
concurrent call. In-process is otherwise acceptable for the checks above.

## 8. Checks not run / limitations

* All 10 requested checks ran. Nothing was skipped for environment reasons.
* macOS arm64 only, as scoped. Linux/Windows and Intel Mac are untested here, though the
  wheel declares support.
* No `mounts=`, `host=`, `tools=`, `Session` concurrency, or sustained multi-tenant load was
  tested; those are different trust surfaces.
* `openpyxl` was intentionally **not** installed on the host ("exactly wasi-python and
  pytest"); the `.xlsx` was generated with the stdlib `zipfile` writer and read by the
  guest's openpyxl.
* wasmtime/CPython memory-safety exploitation is out of scope; only API-level escapes were
  attempted.
* The cold-cache compile numbers (§3) were measured in a separate child process with a
  scratch cache, not in the pytest run (which uses the warm cache).
* The multi-GB unguarded write in check 8 is a deliberate, immediately-deleted measurement on a
  volume with 600+ GB free; it is not part of normal operation.
