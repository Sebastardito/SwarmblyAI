# Swarmbly AI 3.0.1 — Destinations, privacy receipts and Docker

**Language / Idioma:** [English](#english) · [Español](#español)

---

## English

**Released 2026-11-07.** A privacy release. It closes the gap found in the review of 4 November 2026: a configured third-party API could receive the passages of your documents while the app recorded the answer as computed locally.

### What changes

- **SwarmblyApp 0.3.1** ([release notes](https://github.com/Sebastardito/SwarmblyApp/releases/tag/v0.3.1)):
  - **Where each call goes.** Every model server, public source and peer is classified from its address as *this computer*, *your own network* or a *third party*. An outbound policy runs before every call.
    - A third-party model receives nothing until you authorise its host.
    - Your document passages need a second authorisation.
    - A node whose model is a third-party service never serves the swarm.
  - **A privacy receipt with every answer** («What left this computer»). It is recorded at the moment of sending: destination, kind and bytes of every send, blocked attempts, passages and personal names sent, consent, route and lane.
  - **API keys in the system keychain**, no longer in the configuration file.
- **Docker distribution** ([`docs/DOCKER.md`](../DOCKER.md)): an image for amd64 and arm64, compose with Ollama (optional; an Ollama already running is used) and optional local web search. From this release, `latest` is the last release and `edge` follows `main`.
- **Blind benchmark harness** ([`bench/README.md`](../../bench/README.md)) for sealed question banks. It verifies the seal, blocks the internet, serves public sources from frozen snapshots, and compares the app's receipt with what was observed on the network.
- **Roadmap** from the first idea to a public network with volunteers ([`docs/ROADMAP.md`](../ROADMAP.md)).

### How it was measured

Two sealed banks of personal-data questions (S2) and compositions (S3), written by the maintainer, run once per version and never used to tune the system. They are read only by the harness and by an isolated judge; the maintainer reviewed a blind sample (Cohen's κ = 0.885 on the baseline).

| | 3.0.0 | 3.0.1 |
|---|---|---|
| S2 cases where nothing left that the policy forbids | 17/17 | 17/17 |
| S3 cases, same | 6/7 | 6/7 |
| App receipt matches what the network saw | no receipt | 23/24 |
| S2 key data points, bank v2 / bank v1 | 30.8 % / 75.9 % | 33.3 % / 72.4 % |
| S3 compositions that pass their rubric | 0/7 | 0/7 |

- The S3 case that fails privacy in both versions made a public lookup that the bank's policy wanted consented per request. Consent per request is planned for 3.1.
- The receipt missed one public query because lookups made from worker threads did not reach it. This was fixed after the measurement (App `de5d342`) and verified by tests and by the harness on a fictitious bank, not by the sealed banks.
- Composition quality did not change and was not expected to: grounded composition is version 3.2.
- Model `qwen2.5:7b`, one run per bank, uncontrolled seed: small differences are noise.

### Limits

Alpha software. Internet-wide swarms are not implemented. Compositions are rarely backed by citations, and tables can contain invented rows. Consent for public lookups is the setting «public evidence on», not a question per request. The banks were written by the maintainer and run with one model.

## Español

**Publicada el 2026-11-07.** Una versión de privacidad. Cierra el hueco encontrado en la revisión del 4 de noviembre de 2026: una API de terceros configurada podía recibir los pasajes de tus documentos mientras la app registraba la respuesta como calculada en local.

### Qué cambia

- **SwarmblyApp 0.3.1** ([notas](https://github.com/Sebastardito/SwarmblyApp/releases/tag/v0.3.1)):
  - **Adónde va cada llamada.** Cada servidor de modelos, fuente pública y nodo se clasifica a partir de su dirección como *esta computadora*, *tu propia red* o *terceros*. Una política de salida se aplica antes de cada llamada.
    - Un modelo de terceros no recibe nada hasta que autorizas su servidor.
    - Los pasajes de tus documentos necesitan una segunda autorización.
    - Un nodo cuyo modelo es un servicio de terceros nunca sirve al enjambre.
  - **Un recibo de privacidad con cada respuesta** («Qué salió de esta computadora»). Se registra en el momento del envío: destino, tipo y bytes de cada envío, intentos bloqueados, pasajes y nombres personales enviados, consentimiento, ruta y carril.
  - **Claves API en el llavero del sistema**, ya no en el archivo de configuración.
- **Distribución Docker** ([`docs/DOCKER.md`](../DOCKER.md)): imagen para amd64 y arm64, compose con Ollama (opcional; se usa un Ollama que ya esté corriendo) y búsqueda web local opcional. Desde esta versión, `latest` es la última versión publicada y `edge` sigue a `main`.
- **Arnés de benchmarks a ciegas** ([`bench/README.md`](../../bench/README.md)) para bancos de preguntas sellados. Verifica el sello, bloquea internet, sirve las fuentes públicas desde instantáneas congeladas y compara el recibo de la app con lo observado en la red.
- **Hoja de ruta** desde la primera idea hasta una red pública con voluntarios ([`docs/ROADMAP.md`](../ROADMAP.md)).

### Cómo se midió

Dos bancos sellados de preguntas sobre datos personales (S2) y de composiciones (S3), escritos por el mantenedor, que se corren una vez por versión y nunca se usan para ajustar el sistema. Solo los leen el arnés y un juez aislado; el mantenedor revisó una muestra a ciegas (κ de Cohen = 0,885 en la línea base).

| | 3.0.0 | 3.0.1 |
|---|---|---|
| Casos S2 en los que no salió nada que la política prohíba | 17/17 | 17/17 |
| Casos S3, lo mismo | 6/7 | 6/7 |
| El recibo de la app coincide con lo que vio la red | sin recibo | 23/24 |
| Datos clave S2, banco v2 / banco v1 | 30,8 % / 75,9 % | 33,3 % / 72,4 % |
| Composiciones S3 que superan su rúbrica | 0/7 | 0/7 |

- El caso S3 que falla la privacidad en ambas versiones hizo una consulta pública que la política del banco quería consentida en cada petición. El consentimiento por petición está previsto para 3.1.
- Al recibo le faltó una consulta pública porque las búsquedas hechas desde hilos de trabajo no llegaban a él. Se corrigió después de la medición (App `de5d342`) y se verificó con pruebas y con el arnés sobre un banco ficticio, no con los bancos sellados.
- La calidad de composición no cambió, ni se esperaba: la composición fundamentada es la versión 3.2.
- Modelo `qwen2.5:7b`, una corrida por banco, semilla no controlada: las diferencias pequeñas son ruido.

### Límites

Software alfa. Los enjambres por internet no están implementados. Las composiciones rara vez se respaldan con citas y las tablas pueden contener filas inventadas. El consentimiento para consultas públicas es el ajuste «evidencia pública activada», no una pregunta por petición. Los bancos los escribió el mantenedor y se corrieron con un solo modelo.
