## English

**Released 2026-11-09.** Your work in projects, citations you can follow back to the paragraph, memory that keeps only what you confirm, online search only when you approve it, and answers that show where each sentence comes from.

### What changes

- **SwarmblyApp 0.4.0** ([release notes](https://github.com/Sebastardito/SwarmblyApp/releases/tag/v0.4.0)):
  - **Projects.** Each piece of work has a folder of its own (by default `Documents/Swarmbly/<Project>`) with its documents, its memory (glossary and notes) and its conversations. A project's conversations read only that project. Projects export and restore as verified `.swarmbly` packages.
  - **Citations that name the paragraph** of your document (`[D1 p3]`, the same number for a document during the whole conversation) and keep resolving when a folder moves.
  - **Memory with your yes.** Requests to remember, definitions, corrections ("se escribe X, no Y") and concepts you keep apart are proposed under the answer and saved only when you confirm. Every decision is logged. The glossary is a Markdown list you can read and edit.
  - **Online search only when you approve it**, with the exact text in view. Search words can be reviewed as concepts (your glossary, Wikidata, GBIF): "endogamia" offers *inbreeding* or *endogamy*, and your choice can be kept in the glossary for any language.
  - **Answers that show their provenance.** Sentences presented as if they came from your sources, but with no citation, are underlined. Terms you corrected are enforced. Answers that deny what your sources say, or that mix concepts you keep apart, get a warning.
  - **Consent per question** for public lookups about you or your documents; the receipt states what was approved and every word sent.
- **SwarmblyLCE 0.2.0** ([release notes](https://github.com/Sebastardito/SwarmblyLCE/releases/tag/v0.2.0)): level C1 (retrieval over your own documents) moves into the package, with the stable citations, PDFs read without poppler and the glossary format.
- **Blind benchmark harness 1.1.1**: it reports why an app instance could not be configured.

### How it was measured

The two sealed banks (personal-data questions, S2; compositions, S3) were run twice on 9 November 2026, each run read only by the harness and an isolated judge. The first run (App `475ce61`) showed fewer citations and shorter compositions. The cause was diagnosed on an open fictitious battery, never on the banks: reading short documents whole made composition prompts much longer, and the instructions at the top were followed less. The fix (a citation reminder and the requested length at the end of the sources) was measured in a second run, which is the measurement of this release. The maintainer's blind review agreed with the judge on every point (61/61, κ = 1.0).

| | 3.0.1 | 3.1.0 |
|---|---|---|
| Cases where nothing left that the policy forbids (S2 · S3) | 17/17 · 6/7 | 17/17 · 7/7 |
| App receipt matches what the network saw | 23/24 | 24/24 |
| App receipt conforms to the bank's policy | 11/24 | 23/24 |
| S2 key data points, bank v2 / bank v1 | 33.3 % / 72.4 % | 46.2 % / 75.9 % |
| S2 serious errors, bank v2 | 4 | 2 |
| S3 claims backed by a citation, bank v2 / bank v1 | 9/66 / 3/64 | 10/69 / 8/53 |
| S3 compositions with inline citations | 3/7 | 6/7 |
| S3 compositions that pass their rubric | 0/7 | 0/7 |

- Composition is still the weak point. Compositions are shorter than asked, tables can contain invented rows or means, and in bank v2 all three compositions were annulled for serious errors (S3 key data 0/26). One answer still claims a public lookup that was not made. This is the work of version 3.2 (grounded composer, claim auditor, one bounded repair).
- The receipt conformity counts the archived receipt, which includes the case ID added by the harness (the app cannot know it). The S3 case that still fails the bank's receipt policy (bank v1) expected a public lookup the app did not make: with consent per question, the harness never gives that consent.
- Model `qwen2.5:7b`, one run per bank, uncontrolled seed: small differences are noise. Bank v1 S2 was 89.7 % in the first run and 75.9 % in the second, with no change to that path.

### Install note (macOS)

If the folder is synced with iCloud (Desktop or Documents), iCloud can mark the files of the Python environment as hidden and recent Python versions then ignore them. The installer now creates the environment as `.venv.nosync` (which iCloud does not sync) with `.venv` pointing to it. For an existing installation: `mv .venv .venv.nosync && ln -s .venv.nosync .venv && chflags -R nohidden .venv.nosync`.

### Limits

Alpha software. Internet-wide swarms are not implemented. The local 7B model can still reason in the wrong direction, mix languages or add knowledge of its own; the app marks where a sentence comes from, not whether it is true. The banks were written by the maintainer and run with one model.

## Español

**Publicada el 2026-11-09.** Tu trabajo en proyectos, citas que llevan al párrafo exacto, una memoria que guarda solo lo que confirmas, búsqueda en línea solo cuando la apruebas y respuestas que muestran de dónde sale cada frase.

### Qué cambia

- **SwarmblyApp 0.4.0** ([notas](https://github.com/Sebastardito/SwarmblyApp/releases/tag/v0.4.0)):
  - **Proyectos.** Cada trabajo tiene su propia carpeta (por defecto `Documentos/Swarmbly/<Proyecto>`) con sus documentos, su memoria (glosario y notas) y sus conversaciones. Las conversaciones de un proyecto leen solo ese proyecto. Los proyectos se exportan y restauran como paquetes `.swarmbly` verificados.
  - **Citas que nombran el párrafo** de tu documento (`[D1 p3]`, el mismo número para un documento durante toda la conversación) y que siguen resolviéndose aunque la carpeta se mueva.
  - **Memoria con tu sí.** Los pedidos de recordar, las definiciones, las correcciones («se escribe X, no Y») y los conceptos que distingues se proponen bajo la respuesta y se guardan solo si los confirmas. Cada decisión queda registrada. El glosario es una lista en Markdown que puedes leer y editar.
  - **Búsqueda en línea solo cuando la apruebas**, con el texto exacto a la vista. Las palabras de búsqueda se pueden revisar como conceptos (tu glosario, Wikidata, GBIF): «endogamia» ofrece *inbreeding* o *endogamy*, y tu elección se puede guardar en el glosario para cualquier idioma.
  - **Respuestas que muestran su procedencia.** Se subrayan las frases que se presentan como si vinieran de tus fuentes pero no llevan cita. Se respetan los términos que corregiste. Una respuesta que niega lo que dicen tus fuentes, o que mezcla conceptos que distingues, recibe un aviso.
  - **Consentimiento por pregunta** para las consultas públicas sobre ti o tus documentos; el recibo dice qué se aprobó y cada palabra que se envió.
- **SwarmblyLCE 0.2.0** ([notas](https://github.com/Sebastardito/SwarmblyLCE/releases/tag/v0.2.0)): el nivel C1 (búsqueda en tus propios documentos) pasa al paquete, con las citas estables, los PDF leídos sin poppler y el formato del glosario.
- **Arnés de benchmarks a ciegas 1.1.1**: informa por qué no se pudo configurar una instancia de la app.

### Cómo se midió

Los dos bancos sellados (preguntas sobre datos personales, S2; composiciones, S3) se corrieron dos veces el 9 de noviembre de 2026; cada corrida la leyeron solo el arnés y un juez aislado. La primera (App `475ce61`) mostró menos citas y composiciones más cortas. La causa se diagnosticó con una batería abierta ficticia, nunca con los bancos: leer enteros los documentos cortos alargó mucho los prompts de las composiciones y el modelo siguió menos las instrucciones del inicio. La corrección (un recordatorio de citar y la extensión pedida al final de las fuentes) se midió en una segunda corrida, que es la medición de esta versión. La revisión a ciegas del mantenedor coincidió con el juez en todos los puntos (61/61, κ = 1,0).

| | 3.0.1 | 3.1.0 |
|---|---|---|
| Casos en los que no salió nada que la política prohíba (S2 · S3) | 17/17 · 6/7 | 17/17 · 7/7 |
| El recibo de la app coincide con lo que vio la red | 23/24 | 24/24 |
| El recibo de la app cumple la política del banco | 11/24 | 23/24 |
| Datos clave S2, banco v2 / banco v1 | 33,3 % / 72,4 % | 46,2 % / 75,9 % |
| Errores graves S2, banco v2 | 4 | 2 |
| Afirmaciones S3 respaldadas por una cita, banco v2 / banco v1 | 9/66 / 3/64 | 10/69 / 8/53 |
| Composiciones S3 con citas en línea | 3/7 | 6/7 |
| Composiciones S3 que superan su rúbrica | 0/7 | 0/7 |

- La composición sigue siendo el punto débil. Las composiciones son más cortas de lo pedido, las tablas pueden traer filas o medias inventadas, y en el banco v2 las tres composiciones quedaron anuladas por errores graves (datos clave S3: 0/26). Una respuesta sigue afirmando una consulta pública que no se hizo. Es el trabajo de la versión 3.2 (compositor fundamentado, auditor de afirmaciones, una reparación acotada).
- La conformidad del recibo se cuenta sobre el recibo archivado, que incluye el identificador del caso que añade el arnés (la app no puede conocerlo). El caso S3 que aún no cumple la política de recibos (banco v1) esperaba una consulta pública que la app no hizo: con consentimiento por pregunta, el arnés nunca da ese consentimiento.
- Modelo `qwen2.5:7b`, una corrida por banco, semilla no controlada: las diferencias pequeñas son ruido. S2 del banco v1 dio 89,7 % en la primera corrida y 75,9 % en la segunda, sin cambios en esa parte.

### Límites

Software alfa. Los enjambres por internet no están implementados. El modelo local de 7B todavía puede razonar al revés, mezclar idiomas o añadir conocimiento propio; la app marca de dónde sale una frase, no si es verdad. Los bancos los escribió el mantenedor y se corrieron con un solo modelo.
